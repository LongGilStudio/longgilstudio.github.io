В этом руководстве собраны полный рабочий процесс, точные команды и частые ошибки, возникающие при настройке **Bare Git Repository** на внешнем жёстком диске (USB) для надёжного резервного копирования (backup) проекта Unity.

## 1. Знакомство с Bare Repository

- **Bare Repository** — это Git-репозиторий без рабочего каталога (working directory), то есть в нём нет исходного кода, доступного для прямого просмотра или редактирования. Он содержит только содержимое скрытой папки `.git`.
- Его основная задача — **принимать отправленный (push) код** с других компьютеров, работая аналогично локальному серверу GitHub или GitLab на вашем накопителе.

## 2. Точный порядок настройки (пошагово)

### Шаг 1. Включение Git LFS для проекта Unity (локально)

Проекты Unity содержат множество крупных бинарных файлов (изображения, аудио, 3D-модели). Чтобы Git обрабатывал их оптимально, обязательно требуется `Git LFS`.

1. Откройте терминал (Git Bash) в папке вашего проекта Unity (например, `D:\Unity-Projects\GLW`).
2. Скачайте стандартный шаблон `.gitattributes` от GameCI для Unity.
3. Выполните команду для активации LFS:

   ```bash
   git lfs install
   ```

4. Добавьте файл конфигурации в историю Git:

   ```bash
   git add .gitattributes
   git commit -m "Добавить конфигурацию gitattributes для Unity и Git LFS"
   ```

### Шаг 2. Создание Bare Repo на внешнем накопителе

1. Подключите внешний диск к компьютеру (предположим, система назначила ему букву `E:`).
2. Откройте **Git Bash** и перейдите в каталог, где нужно разместить резервную копию (например, `E:\Git`):

   ```bash
   cd /e/Git
   ```

3. Создайте папку для репозитория (по соглашению — с окончанием `.git`).

   > [!IMPORTANT]
   > **Крайне важное примечание:** В Git Bash необходимо использовать прямой слэш `/`, а не обратный слэш `\` из Windows.

   ```bash
   mkdir -p "GLW.git"
   ```

4. Перейдите в созданную папку и инициализируйте Bare Repo:

   ```bash
   cd "GLW.git"
   git init --bare
   ```

### Шаг 3. Связывание проекта Unity с внешним диском (добавление Remote)

1. Вернитесь в терминал (Git Bash) в папке проекта Unity (`D:\Unity-Projects\GLW`).
2. Подключите удалённый репозиторий remote (назовите remote, например, `glw` или `usb`):

   ```bash
   git remote add glw "E:/Git/GLW.git"
   ```

3. Проверьте, правильно ли определился remote:

   ```bash
   git remote -v
   ```
   *(Если вывод содержит 2 строки — `fetch` и `push`, указывающие на `E:/Git/GLW.git`, — всё настроено успешно).*

### Шаг 4. Устранение ошибки безопасности прав доступа (Dubious Ownership)

При отправке кода на накопитель с файловой системой exFAT/FAT32 Git выдаёт ошибку `"dubious ownership"`, поскольку эти файловые системы не хранят права владельца-пользователя так, как NTFS. Из-за этого Git считает репозиторий бесхозным и блокирует работу с ним из соображений безопасности.

**Решение:** явно добавить этот каталог в список доверенных (`safe.directory`):

```bash
git config --global --add safe.directory "E:/Git/GLW.git"
```

### Шаг 5. Отправка кода (Push) на внешний накопитель

Когда всё настроено, выполните команды для отправки всех веток (branches) и тегов (tags), чтобы полностью (на 100%) создать резервную копию проекта:

```bash
git push glw --all
git push glw --tags
```
*(Дождитесь завершения процесса — после этого ваш проект будет надёжно скопирован на внешний накопитель).*

## 3. Частые ошибки (устранение неполадок)

### 3.1. Ошибка создания неправильного имени папки (слипание имён)

- **Симптом:** при запуске команды `mkdir -p E:\Git\GLW.git` в Git Bash создаётся папка с именем `GitGLW.git`.
- **Причина:** Git Bash воспринимает символ `\` как символ экранирования (escape). Он отбрасывает `\` и склеивает `Git` и `GLW` в `GitGLW`.
- **Решение:** при работе с путями в Git Bash всегда используйте прямой слэш `/` или двойные кавычки (например, `mkdir -p "E:/Git/GLW.git"`).

### 3.2. Ошибка `"fatal: 'E:BackupGitGLW.git' does not appear to be a git repository"`

- **Симптом:** при попытке выполнить push возникает ошибка, что удалённый репозиторий (remote) не найден.
- **Причина:** при выполнении команды `git remote add` был использован обратный слэш (`\`), что исказило путь.
- **Решение:**
  1. Удалите неверную конфигурацию remote:
     ```bash
     git remote remove glw
     ```
  2. Повторно добавьте remote с правильным путём:
     ```bash
     git remote add glw "E:/Git/GLW.git"
     ```
     *(Также можно перезаписать адрес командой `git remote set-url glw "E:/Git/GLW.git"`).*

### 3.3. Забыта инициализация Bare Repo

- **Симптом:** даже при правильном пути remote при отправке (push) всё равно выводится ошибка `Could not read from remote repository`.
- **Причина:** внутри папки на внешнем накопителе не была выполнена команда `git init --bare`.
- **Решение:** откройте папку на внешнем накопителе в Проводнике (File Explorer), щёлкните правой кнопкой мыши, выберите **Open Git Bash here** и выполните команду `git init --bare`.
